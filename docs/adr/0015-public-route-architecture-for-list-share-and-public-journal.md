# Public route architecture for List share & public Journal pages

ADR 0004 splits routes into an indexed-SSR homepage and a CSR-shell `_authed` app. List share pages and public Journal pages fit neither: they need SSR (for shareable links to work without JS) but must be `noindex` and reachable while signed out, with no owner-vs-visitor distinction — this ADR adds that as a third rendering category alongside 0004's two, which stay as they are. A new pathless layout route, `src/routes/_public.tsx`, sits as a sibling to `_authed.tsx` (not nested under it, since nesting would inherit its `beforeLoad` auth redirect). It carries no auth check at all — the public pages are strictly anonymous, rendering identically for an owner viewing their own link and any other visitor — and sets `{ name: 'robots', content: 'noindex' }` once in a shared `head()`, inherited by every nested route. SSR stays at the framework default (`true`); no `ssr` option is set explicitly, mirroring how ADR 0004 also relies on the default rather than introducing a new SSR mechanism.

The layout is named `_public` rather than `_shared` (the name floated during the routing research in issue #8) because it should describe the routing/auth contract it enforces — no gate, noindex — not borrow the name of the feature epic that motivated it; an epic name isn't guaranteed to keep describing routing behavior accurately as more gets built under it. Two routes nest under it: `_public.journal.$username.tsx` → `/journal/{username}` for the public Journal view, and `_public.lists.$shareToken.tsx` → `/lists/{shareToken}` for the List share view. The public Journal route is nested under `/journal` rather than exposed as a bare `/{username}` specifically to confine future route-collision risk to that one path prefix, rather than depending solely on ADR 0014's reserved-word denylist as the only defense against a future top-level route colliding with someone's username. The List share route omits `listId` from the path entirely — `shareToken` is already `unique().notNull()` and indexed (ADR 0013), so it's sufficient alone as the lookup key.

Two things this ticket deliberately left out, for separate future tickets rather than by omission: owner-aware affordances on these public pages (e.g. an "Edit" link when the owner views their own share link while signed in — `_public` stays strictly anonymous for now), and a project-wide `robots.txt` route, since the per-route `noindex` meta tag is the actual mechanism and a site-wide file would be redundant.

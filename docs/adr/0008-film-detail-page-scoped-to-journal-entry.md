# Film detail page is scoped to one JournalEntry, not aggregated per Movie

`/journal/{entryId}` shows a single JournalEntry — its Movie's cached summary plus TMDB detail fields fetched live, and that entry's own dateWatched, rating, review, and like status — rather than a Movie-centric page aggregating every JournalEntry (rewatch) a user has for that film. Each `MovieStub` on the journal grid already renders one JournalEntry, so this is what a click naturally lands on, and it keeps the page's Edit button unambiguous: it edits _this_ watch, not "pick which of several." This is a deliberate deviation from `CONTEXT.md`'s existing "Watch count" concept, which is defined per-Movie, not per-entry — a reader might expect the detail page to follow that same per-Movie framing and show a full rewatch history. Instead, the page surfaces watch count only as a read-only note for context.

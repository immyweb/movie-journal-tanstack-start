# Public Journal route path is `/journal/u/{username}`, not `/journal/{username}`

ADR 0015 specified `/journal/{username}` for the public Journal view, nested under `/journal` specifically to confine future route-collision risk to that one prefix. Implementing it (issue #19) surfaced a collision ADR 0015 didn't anticipate: the existing authenticated film-detail route (`_authed.journal_.$entryId.tsx`, ADR 0008) already occupies `/journal/{entryId}` — the same single-dynamic-segment shape one level under `/journal`. TanStack Router sorts routes by path specificity alone (static before dynamic, longest match first), with no supported way to prioritize one dynamic route over another of the same shape at the same depth regardless of which pathless layout (`_authed` vs `_public`) each nests under — confirmed against the router's own docs and reproduced locally, where the authed entry-detail route always won the match, leaving `/journal/{username}` permanently unreachable.

The fix: insert a static `u` segment — `/journal/u/{username}` (`_public.journal.u.$username.tsx`). Three path segments never collide with the entry-detail route's two, while staying under `/journal` per ADR 0015's original reasoning (confining collision risk to one prefix rather than relying solely on ADR 0014's reserved-word denylist). A bare `/{username}` was reconsidered and rejected again here for the same reason ADR 0015 rejected it originally: it reopens the broader top-level collision risk that confining the route under `/journal` was meant to avoid.

This amends only ADR 0015's chosen path for the public Journal view. The `_public` layout, its shared `noindex` head, and the shareToken-only List share route are unaffected.

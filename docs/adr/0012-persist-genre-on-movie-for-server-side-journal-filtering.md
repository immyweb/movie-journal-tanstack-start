# Persist Genre on the Movie cache row for server-side journal filtering

ADR 0005 deliberately kept `genre` as a detail-page-only field, fetched live from TMDB rather than cached, since it was viewed once per JournalEntry on the Film detail page. Filtering the Journal by genre changes that: `docs/SYSTEM-DESIGN.md` already mandates server-side filtering on the Journal page, and that means every list request would otherwise need a live TMDB genre lookup per row. Genre is now cached on the `Movie` row at add-time instead — a `text[]` column, following the same snapshot-at-add-time treatment as `title`, `posterImg`, and `releaseDate` — and a one-time backfill migration populates it for Movie rows cached before this change. Director, cast, language, and runtime stay live-fetched detail-only fields; only genre moved, because only genre needed to be queried across the whole Journal rather than read once per entry.

Decade — the other new Journal filter/sort dimension — is deliberately _not_ given the same treatment: it's computed from the already-cached `releaseDate` at query time, since storing a value that's a pure function of data already on the row would just be redundant write-path cost for no read-side benefit.
